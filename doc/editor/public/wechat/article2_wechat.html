📌 摘要：MCP 是接口，Skills 是流程。一个管"能做什么"，一个管"怎么做"。搞懂这两者的分层架构，是构建企业级 Agent 的第一步。

今天这篇系列第二文，我们就来彻底厘清 MCP 与 Agent Skills 的核心区别与互补关系。

搞懂这一篇，你在设计 Agent 架构时，至少能少踩 50% 的坑。

1 为什么容易混淆？

因为它们经常成对出现。

当你想让 Agent 帮你"分析财报"时，你既需要它有能力获取数据（MCP），也需要它懂得分析逻辑（Skills）。

在很多简单的 Demo 中，这两者往往被混在一起写：把工具调用逻辑直接写进了 Prompt 里。但在企业级应用中，这种耦合会带来巨大的维护灾难。

为了便于理解，我们先用一个职场类比：

🏢 职场类比
MCP 就像公司的 IT 系统权限。它决定了你能不能登录 CRM 系统、能不能查数据库、能不能调用打印机。它解决的是 "能不能做" 的问题。
Skills 就像员工的 岗位 SOP 手册。它规定了拿到数据后先算什么、再算什么、报告怎么写、风险怎么提示。它解决的是 "怎么做" 的问题。
一个刚入职的员工（Agent），既需要开通系统权限（MCP），也需要领取岗位手册（Skills），才能正式上岗。

2 核心区别对比表

为了更直观，我们整理了一张对比表，建议收藏保存：

维度MCP (Model Context Protocol)Agent Skills
定位能力层 (Capability)流程层 (Process)
核心问题如何连接工具/数据？如何执行专业任务？
表现形式协议 + Server/Client技能包 (如 SKILL.md + 脚本)
加载方式运行时动态发现/连接按需渐进式加载
关注点标准化、安全性、通用性业务逻辑、领域知识、复用性
变更频率低 (接口稳定)高 (业务逻辑常变)
类比USB-C 接口员工培训手册
💡 关键洞察：MCP 倾向于标准化连接，让不同模型能统一调用工具；而 Skills 倾向于知识沉淀，让业务专家的经验能被 AI 复用。

3 分层架构：它们如何协同工作？

在理想的 Agent 架构中，它们处于不同的层级。请看下面的架构图解：

工作流程解析：

  • 用户输入：提出模糊需求。
  • Skills 层介入：匹配到"财务分析技能"，加载对应的 SOP 流程。
  • 流程执行：SOP 指示第一步需要"获取财报数据"。
  • MCP 层介入：Skills 调用 MCP 定义的 query_financial_db 工具。
  • 结果返回：MCP 返回数据，Skills 继续执行下一步"计算比率"。
  • 最终输出：按 Skills 规定的格式生成报告。

    • 这种分层的好处是什么？

    • 解耦：如果数据库变了，只改 MCP Server，不用动 Skills 逻辑。
    • 复用：同一个"查询数据库"的 MCP 工具，可以被"财务分析"、"销售报表"等多个 Skills 复用。
    • 安全：MCP 层统一做权限控制，Skills 层只管业务逻辑，不用担心越权。

    4 典型协作场景举例

    为了让大家更有体感，我们看三个具体场景：

    🏦 场景一：金融投研助手
    MCP 负责 连接 Wind 终端、彭博 API、公司内部数据库。提供 get_stock_price, get_financial_report 工具。
    Skills 负责 定义投研分析框架。比如"先分析营收增长率，再分析现金流，最后给出评级"。它告诉 AI 如何运用 MCP 提供的数据。
    价值：数据实时准确（MCP），分析专业合规（Skills）。
    📝 场景二：自动会议纪要
    MCP 负责 连接飞书/钉钉 API、录音文件存储、Notion 数据库。提供 get_meeting_record, create_note 工具。
    Skills 负责 定义纪要格式。比如"必须包含：决议项、责任人、截止时间"。它告诉 AI 如何整理 MCP 获取的内容。
    价值：操作自动化（MCP），输出标准化（Skills）。
    🔍 场景三：竞品调研 Agent
    MCP 负责 调用搜索引擎、爬虫工具、社交媒体 API。
    Skills 负责 定义调研维度。比如"重点关注对方的定价策略、新功能发布、用户差评"。
    价值：信息获取广（MCP），调研深度深（Skills）。

    5 常见误区澄清

    在结束之前，我必须澄清三个常见的误区，这也是很多开发者容易踩坑的地方：

    ❌ 误区 1："有了 MCP 就不需要 Skills 了"
    ✅ 真相：MCP 只提供了"枪"，没教你"怎么瞄准"。没有 Skills，AI 拿到数据后可能只会罗列，无法形成专业结论。
    ❌ 误区 2："Skills 能替代工具调用"
    ✅ 真相：Skills 里虽然可以封装脚本，但对于实时数据（如股价、库存）、私有系统访问，必须通过 MCP 这样的标准化协议连接，否则无法保证实时性和安全性。
    ❌ 误区 3："它们是竞争关系，二选一"
    ✅ 真相：它们是互补关系。MCP 是基础设施（Infrastructure），Skills 是应用逻辑（Application Logic）。就像"操作系统"和"办公软件"的关系。

    6 总结与建议

    回到我们的公式：

    超级 Agent = 大模型（大脑） + MCP（手） + Skills（手册）

    请先关注 MCP，先把数据链路打通，确保 Agent 能"摸到"数据。

    📊 如果你是业务专家

    请重点关注 Skills，思考如何将你的经验转化为标准化的流程文档。

    🏗️ 如果你是架构师

    请设计好分层架构，让 MCP 和 Skills 解耦，便于未来扩展。
